# Numbers

*Diataxis type: reference.*

The ledger Section 20 asks for: every headline number this project publishes,
with the result file it comes from. Nothing here is typed from memory and nothing
here is rounded from a number that is not in `experiments/results/`.

**How to check any row.** Every cell file is
`experiments/results/<model>-O<level>-<budget>-n<batch>-fp32-<class>.json`, and
an ablation row adds `-ablate-<pass>`. The field names below are the schema's
own. `report/generated/macros.tex` carries the same numbers as LaTeX macros,
generated by `experiments/results_to_tex.py`, and
`test/Python/test_traceability.py` asserts that the README's table and that file
both trace back here.

**Provenance of everything on this page.** Measured at commit
`d4210f35`, schema version 1, `GENERATOR_VERSION` 1.1.0, content hash
`237d4c57`. 175 cells, on an Intel Core i7-14700K under WSL2.

## Per model, at the default budget and each model's declared batch

Instruction counts are `instruction_count`, taken from the simulator's own
`stats.instructions` and never counted from anything else. Cycles are
`simulation.simulated_cycles`. Bytes are `simulation.dram_bytes_total`.

| Model | Batch | `-O0` | `-O1` | `-O2` | Cycles at `-O2` | DRAM bytes at `-O2` | MACs |
|---|---|---|---|---|---|---|---|
| `lenet` | 1 | 25 | 25 | 25 | 17766.25 | 250000 | 416520 |
| `depthwise_separable` | 1 | 12 | 12 | 12 | 1324 | 3008 | 12800 |
| `resnet_block` | 1 | 14 | 14 | 14 | 1626 | 8800 | 73728 |
| `inception_block` | 1 | 14 | 14 | 14 | 2398.5 | 8624 | 55296 |
| `conv_bn_relu_stack` | 1 | 23 | 23 | 15 | 1160.5 | 4144 | 50720 |
| `dilated_stack` | 1 | 13 | 13 | 12 | 1234.0625 | 5364 | 41706 |
| `lenet_batched` | 4 | 25 | 25 | 25 | 20000 | 259528 | 1666080 |

`macs` is the **raw** count and is the only one an energy model ever sees.
`effective_macs`, the utilization scaled figure the cycle charge used, is
recorded per cell beside `utilization` and `delta` so the charge can be
reconstructed rather than trusted, and it is deliberately not in this table:
Section 5.5 forbids the energy path from ever seeing it, and a headline table is
where the two would first get confused.

**`-O1` is exactly `-O0` on every model in this suite.** That is a measurement
and not an omission, and it is worth stating plainly rather than leaving a reader
to infer that `-O1` does nothing in general. `-O1` is constant folding and one
canonicalization. No model here has an elementwise operation both of whose
operands are constants, so the folder has nothing to fold, and with nothing
folded the canonicalization has nothing dead to clean up. P9 asked P10's report
to say this out loud; this is it.

**`-O2` differs from `-O0` on exactly two models**, and the two savings are the
two nonzero ablation rows below seen from the other side: `conv_bn_relu_stack`
loses eight instructions to the batch norm fold and `dilated_stack` loses one to
the bias fusion.

## The ablation table

Section 16.2's leave one out ablation: `-O2` minus one pass, at every budget,
with the ablatable set read from the compiler at run time. The delta is the
ablated cell minus its baseline, so **a positive number is what the pass saves**.

| Pass | Instruction delta | Where | Cycle delta |
|---|---|---|---|
| `-npu-fold-batchnorm` | 8 | `conv_bn_relu_stack` | 212 |
| `-npu-fuse-bias` | 1 | `dilated_stack` | 9.625 |
| `-npu-constant-fold` | 0 | everywhere | 0 |
| `-canonicalize` | 0 | everywhere | 0 |
| `-npu-fuse-ops` | 0 | everywhere | 0 |
| `-cse` | 0 | everywhere | 0 |
| `-sccp` | 0 | everywhere | 0 |
| `-symbol-dce` | 0 | everywhere | 0 |

The rows are identical at both budgets. Every pass is zero on every model not
named in the "where" column.

### The zero rows, each with its reason, because a zero is not self explanatory

A table of zeros with no prose beside it reads as "these passes are worthless",
and that is not what any of these rows says.

- **`-sccp` is zero for a structural reason and would be zero on any input this
  compiler can currently produce.** It propagates constants through the call
  graph, and every module here holds exactly one function and no calls, so there
  is nothing for it to cross. `test_sccp_has_nothing_to_do_on_a_single_function`
  asserts the one function property rather than the outcome, so a compiler that
  grew calls makes that test red instead of leaving this sentence stale.
- **`-symbol-dce` is zero for the same kind of reason.** It removes a private
  symbol nobody calls, and every module here has one public function.
- **`-npu-constant-fold` is zero because no model in this suite has an
  elementwise operation both of whose operands are constants.** This is the same
  fact as `-O1` equalling `-O0`.
- **`-npu-fuse-ops` is zero because it is numerically and structurally inert by
  design.** Forming an `npu.fused_op` region adds operations at the tensor level,
  measured here as 34 to 38 on `conv_bn_relu_stack`, and the lowering flattens
  them back into the same instructions. `docs/PASSES.md` claimed that in prose
  before P10; this row is the measurement.
- **`-cse` is zero because these models are generated from a seed and none of
  them contains two identical operations over identical operands.**
- **`-canonicalize` is zero, and this row is the interesting one, because
  canonicalization is not idle.** Measured on `conv_bn_relu_stack` at `-O2`, the
  second canonicalization takes the function from 38 operations to 24. Removing
  it does not change the instruction count, because `-cse` then arrives at the
  same 21 operations on its own: MLIR's CSE erases trivially dead operations as
  it walks. **A leave one out ablation cannot see a pass whose work another pass
  would have done**, which is a known limit of the design and is now a measured
  one here. The honest reading of this row is "nothing in this suite needs both",
  not "canonicalization does nothing".

That last row is the clearest thing the Section 16.2 instrumentation has bought
so far. The before and after operation counts per pass are what turn a zero
delta into a diagnosis; without them the row would have read as a pass with no
effect and `docs/PASSES.md` would have recorded it that way.

## Numerics

| Number | Value | Source |
|---|---|---|
| Largest movement of any level against `-O0` | 8.941e-08 | `conv_bn_relu_stack-O2-default-n4-fp32-normal`, `accuracy.max_abs_movement_vs_o0` |
| Largest distance to `onnxruntime`, any cell | 7.153e-07 | `inception_block-O2-default-n4-fp32-normal`, `accuracy.max_abs_error_vs_onnxruntime` |
| End to end absolute band | 5e-5 | `npu_frontend.tolerances.ABSOLUTE_TOLERANCE` |
| SQNR of `-O2` against the `-O0` answer | 136.87 dB | `conv_bn_relu_stack-O2-default-n1-fp32-normal`, `accuracy.sqnr_db_vs_fp32_simulated` |

The largest distance to `onnxruntime` is 70 times inside the band, which is the
relationship Section 17.4 asks a tolerance to have: close to observed rather than
comfortably wide, but wide enough to survive a host whose `onnxruntime` picks
different kernels. `npu_frontend/tolerances.py` carries the measurement the band
was set from and the P9b runs that turned its per host caveat into a number.

**Only one pass in this pipeline moves a number, and the ablation table proves
it from the other side.** `-npu-fold-batchnorm` rewrites a convolution's weights
and bias at compile time, which changes the accumulation order; ablating it
returns `max_abs_movement_vs_o0` to exactly 0.0 on `conv_bn_relu_stack`. Every
other ablation leaves that field where the unablated `-O2` cell has it.

**Top 1 agreement is 1.0 and cosine similarity is 0.999999999999965, and neither
is used to rank anything.** Section 16.1 requires both to be recorded and
forbids ranking on them, and the measurement is why: this suite's models are
seeded and never trained, so their logits are unseparated, argmax agreement
saturates and cosine similarity has no resolution. Every result file carries that
sentence in `accuracy.ranking_metric` beside the two numbers, so a reader meets
the caveat at the same time as the figure. SQNR is the metric that moves.

## What is not here, and when it arrives

Every result file carries these fields with `null` and a reason naming the phase
that fills them. They are listed here so that this page is a complete account of
what has been measured rather than a selection of what came out well.

| Field | Arrives at |
|---|---|
| `roofline_bound_cycles`, `operational_intensity`, `roofline_verdict` | P11, Section 16.6 |
| `scalesim_cycles` and both coverage fractions | P11, Section 16.3 |
| `energy_pj`, `energy_pj_per_inference`, `edp`, `area_mm2`, `technology_node` | P11, Section 16.4 |
| `tiling_choices` | P13 |
| `quant_boundary_crossings`, `per_layer_sqnr_db`, `max_abs_error_vs_fp32_simulated` | P14 |

**No number on this page is an estimate.** Where a phase has not measured
something, the field is null with a reason rather than a plausible figure, and
`npu_frontend.results.values_of` refuses to average a null into a table rather
than reading it as a zero.
