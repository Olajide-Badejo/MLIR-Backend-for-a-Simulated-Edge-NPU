# between an environment that is described and one that is pinned.

# Regenerate with:
#
#   ~/npu-venv/bin/pip freeze > /tmp/freeze.txt

# then splice the frozen lines under this header, keeping the index line.

# There are no editable installs and no local path installs in this
# environment: `pip freeze` produced no `-e ` line and no `@ file://` line, so
# every requirement below resolves from an index.
#
# The extra index is load bearing and is the reason a clean install of this
# file failed the first time I tried it. torch is pinned as 2.13.0+cpu because
# that is the build that is installed, and the +cpu local version exists only
# on the PyTorch CPU index, never on PyPI. Dropping the +cpu suffix to make
# PyPI resolve it would be worse than a broken install: it would silently pull
# the CUDA build, change what reference generation runs on, and pull roughly
# two gigabytes of CUDA wheels onto a machine whose GPU this project does not
# use. Section 3 records the installed torch as a +cpu build and this line is
# what keeps that true on a rebuild.
